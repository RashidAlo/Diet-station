Overlays & Sheets

One structure for every surface that presents over a screen — how it arrives, how it's driven, where its actions live, and how it leaves. Meal selection is the reference implementation; the demos below are live.

The contract

Every overlay presents the same way: it slides in from the bottom while the screen behind darkens under a diffuse, transitioned dark layer. Per the overlay rule, that scrim never travels — it dissolves in place; only the sheet moves, on the house spring. Exit reverses both.

scrim rgba(11,14,18,.42–.45), opacity only, .32s ease · sheet translateY(103%) → 0, .55s cubic-bezier(.32,.72,0,1) · radius: partial sheets 24 24 0 0, near-fullscreen overlays 44 44 0 0 (under review: auth's Figma frame draws 38 and ships 38 — whether the radius law or Figma fidelity wins is Rashid's call; don't “fix” auth to 24 meanwhile) · sheet shadow 0 -14px 44px rgba(0,0,0,.24).

Two modes of interaction

Static sits where it presents. Expanding can be swiped up — it travels with the finger and snaps into full screen (corners growing 24→44 as it docks). Try both; drag the sheets by their headers.

Drag tracking kills the transition (.drag class); release snaps to the nearest state on the house spring. Expanding snap points: rest height and full screen (top inset ~10px). All thresholds below.

Scroll-driven expanding (reference: the meal selection screen, Rashid's settled mechanism) — when the sheet's own content scroll drives the docking, sheet and content travel as one piece, 1:1 with the finger (y = gap − s, radius riding y, a headroom pad keeping content glued to the frame) until the frame docks; content then keeps scrolling. The only velocity event is the natural arrest at the top — the same stop a native sheet makes at its detent. A scroll that dies mid-zone detents to the nearest state after momentum ends. Iteration history (recorded in the flow): content-freeze and eased-frame profiles were both tried and superseded by this 1:1 one-piece feel — his taste call.

The action bar

Every overlay carries a top action bar. Its content is feature-dependent — but placement is law: actions live on the right.

With controls

When the overlay has simple controls, they form the Apple-style dual capsule — confirm (check) and clear (X), divider between — pinned right. Reference: meal selection's capsule at right: 16px, 44px tall, radius 22, frosted glass.

Without controls

When an overlay has nothing to confirm, the lone X takes the same right-side seat. Never left, never floating elsewhere.

Over imagery the bar sits on a top gradient (rgba(0,0,0,.22) → 0) with a glass X (blur 12 + saturate 160%) — meal details is the reference. Navigation steps, titles and feature controls fill the left and center as each feature needs.

Optional trait: drag-to-close

Sheets whose exit needs no confirmation may close by pulling down — an opt-in trait, granted per screen. Values from the meal-details reference:

tracks only when the sheet's scroller is at the top (scrollTop ≤ 0) · the sheet follows the finger with rubber-band resistance ×0.42 · release past 195px closes; short of it, the sheet springs back · during tracking the transition is off (.drag), so the sheet is glued to the finger · one scroller chains content scroll, header collapse and the dismiss pull in a single gesture — no separate grab zones.

Granted: meal details (reference), sign-in · withheld where closing loses work or aborts a journey mid-step (auth's OTP screen, auto-closing success) — those keep the X as the only exit, optionally with a confirm alert. The trait is per-screen, not per-flow: one flow can grant it on some screens and withhold it on others, decided by what an accidental pull would cost.

Dev handoff

// ── Native (SwiftUI) ──────────────────────────────────────────────
// static sheet:
.sheet(isPresented: $show) { SignIn() }
  .presentationDetents([.height(420)])          // one detent = static
  .presentationCornerRadius(24)
// expanding sheet (two snap points, corners grow as it docks):
  .presentationDetents([.medium, .large])
// drag-to-close trait:
  .interactiveDismissDisabled(false)            // granted
  .interactiveDismissDisabled(true)             // withheld (X only)
// scrim: system dimming already dissolves in place — never animate a cover;
// a cover presenting a WEB surface stays transparent + non-animated (solo=1).

// ── Web ──────────────────────────────────────────────────────────
// scrim:  rgba(11,14,18,.45); opacity 0→1, .32s ease  (NEVER transform)
// sheet:  translateY(103%)→0, .55s cubic-bezier(.32,.72,0,1)
//         radius 24 partial · 44 near-fullscreen · shadow 0 -14px 44px rgba(0,0,0,.24)
// expanding: track drag with transition off; on release snap to nearest of
//         [rest height, full (top −10px)] on the house spring
// drag-to-close (opt-in): only when scrollTop <= 0; follow at dy*0.42;
//         release > 195px → close, else spring back
// action bar: actions RIGHT — dual capsule (confirm|clear, 44h r22, frost)
//         when controls exist; lone X right otherwise; top gradient over imagery
