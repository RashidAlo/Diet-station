The Components tab — contract

Rashid, 2026-09-13: every flow on the desktop hub gets a Components tab. It lists the components on each screen with their documentation, and it doubles as a playground for trying their states. It drives the real prototype, not rebuilt copies, so the playground cannot drift from what ships. This is the one-pass spec; three lanes build against it.

LAYOUT       desktop flow page, 4th lab tab after Prototype · User flow · Dev handoff.
             Not rendered on mobile or in the app shell; resizing into mobile while on
             it returns to Prototype. It covers the WHOLE viewport (three panes plus a
             device frame do not fit beside the sidebar) and repeats the tab switcher
             in its own header. Every flow has the tab. Without a registry entry it
             shows "No components documented for this flow yet".
               left    screens, each listing its components
               middle  the selected component: summary, anatomy/values, states,
                       link to its /system/ page
               right   a LIVE instance of this flow in a device frame (402 x 874,
                       scaled). Picking a state drives it; the component is outlined.

REGISTRY     system/components.json, owned by Design System (the documentation is
             ours). It is NOT in flows.json, which the admin publish writes.
             { "v": 1, "flows": { "<flow-id>": {
                 "screens":    [ { "id", "name" } ],
                 "components": [ { "id", "name", "screen", "kind",
                                   "summary", "values": [ "..." ],
                                   "doc": "system/overlays.html#controls",
                                   "states": [ { "id", "label", "note"? } ] } ] } } }
             kind: control | surface | content | feedback
             ids: kebab-case and SHARED when it is the same component in another
             flow (sheet-x, dual-capsule, date-tile, price), so docs are written once.

INSTANCE     iframe src = the flow's own path + ?labframe=1&v=<now>
             Created when the tab opens and REMOVED when it closes. A second live copy
             behind the Prototype tab would cost CPU and could play sound. Every visit
             boots fresh. Selecting a component drives its FIRST state.
             labframe=1 means lab-shell builds NO chrome (tabs, chip, menus) and the
             flow renders its mobile layout at scale 1 with no desktop sidebar and no
             triple-tap lab menu.

PAGE API     each flow page defines, once it can drive itself:
               window.DSComponents = {
                 v: 1,
                 show(componentId, stateId)  -> Promise<{ ok: bool, why? }>
                     navigates to the component's screen, puts it in the state, and
                     resolves when the motion has SETTLED (a flag, not a timer)
                 rect(componentId)           -> { x, y, w, h, r? } | null  viewport px;
                                                r = corner radius, optional
                 reset()                     -> Promise   back to the boot state
               }
             and then posts parent.postMessage({ t: 'ds-components', v: 1,
               ids: [ ...componentIds it can drive ] }, '*').
             The tab calls the API directly on contentWindow (same origin) and
             treats the post as "ready". Ids the page does not list, or a show()
             resolving ok:false, render as DOCS ONLY with the reason.
             Tab-side watchdogs only stop a stuck page from hanging the tab; the page
             still owns the settle flag. No ds-components within 6s -> everything is
             docs only ("this flow hasn't adopted the Components contract yet"). A
             show() unsettled after 5s -> "didn't settle".

STATE RULE   a state is a REAL CODE PATH. show() calls the same function the user's
             gesture calls (setLevel, the rip's completion, the scrubber's arm), never
             a class toggled to look right. If the path lives inline in a gesture
             handler, extract it into a function both call; that refactor is part of
             adopting the tab. Only when no path exists may a state be faked, marked
             "simulated": true in the registry and labelled as such in the tab.
             A state must be reachable from ANY other state: show() resets what it
             needs to, and the tab never assumes an order.

OUTLINE      the tab draws the outline over the iframe from rect() x scale, re-read
             every frame for the duration of the settle, AND on the instance's scroll
             and resize events, so moving or scrolled components stay boxed. Red
             1.5px, 4px outset, radius = (r + 4) x scale, or 8px x scale when the page
             gives no r.

NATIVE       the playground shows the WEB rendering. Where the app draws the
             component natively (twins), the state's note says so and links Ruling 3.
             The tab never claims to preview native glass.

OWNERS       Design System  this contract, system/components.json, every doc
             Hub            the tab in lab-shell.js, labframe=1 in lab-shell (no tabs,
                            tab bar, chip, back, lab menu, three-finger gesture or
                            sidebar resizer), outline, watchdogs
             each flow lane labframe=1 in its page (its own desktop sidebar and lab
                            menus), window.DSComponents, the
                            ds-components post, extracting state paths into functions
PILOT        rewards (idle lane, small, setLevel already exists): sheet-x, coupon
             (bronze · silver · gold · vip · redeemed), level badge.

EVIDENCE     on the desktop hub, rewards → Components:
             1  every registry component is listed under its screen, with its doc
             2  each state drives the live instance, reachable from every other state
                in any order, and the outline boxes the component when settled
             3  a state the page cannot drive shows as docs only, with the reason
             4  the Prototype tab is unchanged, and the mobile/app views show no
                Components tab
             5  labframe=1 shows no lab chrome inside the instance

What this does NOT cover: interactions that need a finger (the rip gesture, the scrub drag). The tab can put a component into the state a gesture ENDS in, but the gesture itself is tried on the Prototype tab. No component is rebuilt in isolation either: if a component needs a standalone specimen, that belongs on its /system/ page.

The two glass recipes

Dark glass (State=default): a 4-fill stack (#000 25% / #FFF 25% / #444 60% / #F8F8F8 20%) + Figma’s GLASS effect (r6) + specular inner shadows — the black button as chrome.
Tinted glass (every other state): white backing at 94% + a Tint layer bound to surface/{state}/default + the same GLASS r6 and inner-shadow gloss. In the app this maps to the lab’s Tier-3 refractive recipe (liquid-glass-js / SwiftUI .glassEffect(.regular.tint(...))).

Fresh from today's Figma pass: glass previously existed only for the black and secondary buttons (and secondary’s hover/focus/disabled were solid fakes — now rebuilt as real tinted glass). I built the 20 missing glass variants (warning, error, success, information, Highlight × 4 statuses) fully token-bound, sitting in a grid directly below the Button set on the → Button page — select all 20 and drag them into the set frame and Figma absorbs them as variants (the remote API can’t reparent text while your licensed fonts are local-only). Note: Highlight has no text/border tokens of its own, so its glass follows the solid’s convention (secondary text tokens) — worth a decision.

Sheets

Everything secondary presents as a bottom sheet: settings, sign-in, lab menus. Sheet ground #FBFBFC, top radius 24, over a #0B0E12 veil at 45%.

In: translateY(105%) → 0 over .42s cubic-bezier(.25,.9,.3,1); veil fades .28s ease. Out: reverse, accelerating (cubic-bezier(.5,0,.8,.6) on full-screen flow sheets). Max height 78vh, content scrolls inside. The full system — interaction modes, the action-bar law, drag-to-close — lives on Overlays & Sheets.

Glass

Three tiers, one law. Glass is chrome — it floats over content and must read as material, not decoration. The law: adaptive contrast is mandatory — sample the backdrop behind every glass control; if it reads light (relative luminance > 0.5), flip the content to #0B0E12, else white.

TIER 1

CSS Liquid Glass — simple chrome

Close buttons, tab bars, static nav. Pure CSS: translucent white fill, blur + saturate, and the specular "seat" — an inset top highlight plus hairline ring. This page's own X is the recipe, live.

Let’s get Started

Fill rgba(255,255,255,.16–.5) by backdrop · backdrop-filter: blur(24px) saturate(190%) (tab bars go to blur(30px) saturate(200%) contrast(1.06)) · seat: inset 0 1.5px 1px rgba(255,255,255,.75), inset 0 0 0 .8px rgba(255,255,255,.5), 0 8px 24px -10px rgba(0,0,0,.3). The right-hand X above shows the contrast flip over the light band.

TIER 2

Frosted surface — over live content

In-app surfaces: coupons, cards, nav bars over scrolling content. Frosted CSS with the Figma fill stack — never refractive glass over anything that moves (a refracted snapshot reads frozen and fake).

Frosted surface blur 14 + saturate 170% over the real pixels behind it

backdrop-filter: blur(14px) saturate(170%) (12–18px by context) + white fill at ~.3 + inset seat ring · dynamic overlays (gauges, fills) sit ON the frost as ~94%-opacity canvases so the blur breathes through · Figma blend layers (plus-lighter) must blend with the sheet — no filter/clip-path/ z-index between them or the blend isolates and washes out.

TIER 3

Refractive glass — liquid-glass-js

Nav and action buttons (X, CTA) over static-ish backdrops get true WebGL refraction — the vendored dashersw/liquid-glass-js Container rendering an html2canvas page snapshot through the DietStation shader. The one global recipe lives in glass.json; dial it in the Glass Lab.

Open Glass Lab

Published recipe: blur 5 · frost .07 · rim .015 / 0.8 · edge 0 / .14 · corner boost .03 · ripple .06 · every flow fetches glass.json?v=Date.now() and layers the device draft on top · scaled stages must set contextScale = stageScale or falloffs break.
