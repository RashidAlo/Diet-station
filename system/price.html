DietStation Design Lab

Price

One big number, and a single row of smaller parts hanging off it. Every price in the product is this component at a different size with different slots switched on — values read from the Figma Price set, nothing invented.

The law

KD139.000
The price is one row
ONE NUMERAL CARRIES THE SIZE. EVERYTHING ELSE IS A SATELLITE, AND EVERY SATELLITE HANGS FROM THE SAME TOP EDGE.
The currency, the decimals, the struck old price, the /day — none of them competes with the numeral, and none of them sits on its own line. They align to the top, not the bottom and not the baseline, so the row reads as one object however many parts are switched on. In CSS that is one property: align-items: flex-start. Bottom-aligning is the single most common way this gets broken, and it is the thing to look for in review.

Anatomy

Six slots, always in this order. Only the numeral is mandatory — every other slot is a switch, which is what makes one component cover every price in the app.

one top edge
− KD159.000 KD139.000/day
minus
Optional “−” prefix. Used where the price is a deduction — a coupon line, a saving — never on a price the customer pays.
was
The old price, struck through, in grey (#999999) at Semibold. A whole price in miniature: it carries its own currency and decimals.
cur
The currency. Bound in Figma to the Reusable/KD string variable, so it becomes د.ك in the Arabic mode rather than being retyped.
num
The numeral — the only part that changes typeface by type, and the only one that carries the size of the component.
dec
The decimals, including the separator. Its own component in Figma (Decimal), always smaller than the numeral, always top-aligned.
per
The period suffix — /day, /Month. Bound to the Results A/Day string variable, so it localises with the rest.

Figma property names, for the handoff: Minus, Discount, KD, Price (text), Decimal, per day — booleans except Price. Defaults: currency and decimals on, discount, minus and per-period off.

Pick and choose

The methodology, live. Choose a type and a size, switch slots on and off, and take the markup — the same three decisions a designer makes in Figma and a developer makes in code.

The ramp

    
Eight sizes. The numeral’s typeface is what separates the types:
      Primary is Urbane Rounded in brand red and is for the price a screen is about;
      Secondary is Proxima Nova in ink for prices inside lists, rows and cards;
      Tertiary is the unit-rate line, where the numeral shrinks to make room for the
      suffix. Every value below was read from the Figma set, not eyeballed.

    

    
Read as numeral / line-height · currency · decimals. The
      line-heights are Figma’s and belong to the Figma file — see the next card for
      why they must not be copied into CSS.

  


  

    
What “top-aligned” actually means

    
Worth its own card, because getting this wrong is what every broken price in
      the product has in common — and because the obvious implementation is the wrong one.


    

      
Measured, not assumed

      
IT IS THE INK THAT ALIGNS, NOT THE TEXT BOXES.

      
Asked for the tight render bounds of every part of Primary xxxl and
        Tertiary md, Figma answers 0, 0, −0.3,
        −0.4, −0.5 — every part’s first painted pixel on one
        line, to within half a pixel. Not baselines, which differ; not line boxes, which differ
        more. Cap tops.

    


    
Why copying the line-heights fails

    
The Figma file achieves that with per-part
      line-heights — 19px on a 30px numeral, 22 on the currency, 28 on the decimals. Those
      numbers are tuned to Figma’s text layout, and putting them in CSS does not
      reproduce the result. Measured in the browser with the exact same values, the ink tops of
      Primary xxxl land at −0.52, 5.76 and 8.61 — a 9px
      spread, with the decimals visibly sagging. That is the same defect the audit found in
      checkout, arrived at from the opposite direction: there by bottom-aligning on purpose, here
      by copying the spec faithfully.


    
What works instead

    
Give every part line-height: 1, then
      push each satellite down by the difference between its cap offset and the
      numeral’s. That offset is a fixed fraction of font-size for a given family, so it is
      one constant per typeface and one calc() per slot — no magic numbers per size,
      and it survives a size being changed.


    

      
Correction — a check worth not copying

      
A CHECK THAT CANNOT FAIL IS NOT A CHECK.

      
This page first claimed the six slots agree to 0.01px, measured by reading
        marginTop + k × fontSize off the computed styles. The Checkout lane pointed
        out that this is an algebraic identity: marginTop is set to
        numSize·kNum − ownSize·kSat, so adding kSat·ownSize back always
        returns numSize·kNum — the same value for every slot, for any k
        whatsoever. It would report a perfect zero with the constants wildly wrong and the
        ink visibly drifting. They had made the same mistake one layer down an hour earlier,
        measuring box tops that flex-start makes identical by construction. Two
        lanes, each measuring the quantity that could not disagree with itself.


        What that check does establish is worth keeping: that the rule reached every slot.
        It verifies wiring, not correctness.

      
The general form, from the Hub
        lane: an audit that finds nothing has told you something only if it could have
        found something.

      
Their manifest sweep came back clean and was worth running, because a
        wrong target or a missing path would have shown — and its one false positive was the
        proof: a resolver that complains about something is a resolver that is running.
        A green result is only as meaningful as the red result it was capable of
        producing. Before trusting a passing check, ask what would have made it fail; if
        the answer is nothing, you have measured your own assumptions.

    


    
What the ink actually does

    
The check that can fail is a pixel probe: rasterise
      each run and find its topmost inked row. Measured that way the cap ratios are
      Urbane '139' .1792, Proxima '139' .1167,
      Proxima 'KD' .1250, Avenir '139' .0688 — close to the constants
      in use but not identical, and note that the currency’s letters start lower than
      digits do, because Proxima’s lining figures overshoot its cap height. So there is
      a real residual, and it is sub-pixel: my probe puts the currency ~0.19px low of the
      numeral; Checkout’s independent one (16×, swept across three ink thresholds)
      puts it ~0.6px the other way. Different rasterisers, same conclusion — well under a
      pixel, invisible, and not worth chasing to zero. It is written down so the next person
      who measures pixels finds a documented number instead of thinking they have found a
      bug.

    
If you do measure, compare cap-bearing runs only. A /day
      has no capitals, so its ink starts at x-height and will always read low — that is the
      glyphs, not the alignment.

    
k is per run, not per family — the reason
      this component gets away with two constants is that every slot in a price renders digits
      or capitals. Measured on Urbane Rounded: digits .1771 at weight 300 and 600
      alike, capitals .184, but Kcal .1493, because the
      l is an ascender and ascenders out-top capitals. Outside prices — a macro
      readout, a count beside a label — measure on the glyphs the run actually renders, and see
      the mixed-size row law on
      Foundations.

    

      
/* the per-family constant — re-measure if a font file is ever replaced */
const ctx = document.createElement('canvas').getContext('2d');

function capOffsetRatio(weight, family) {
  ctx.font = `${weight} 100px ${family}`;
  const m = ctx.measureText('139');
  const box = m.fontBoundingBoxAscent + m.fontBoundingBoxDescent;
  const halfLeading = (100 - box) / 2;
  return (halfLeading + m.fontBoundingBoxAscent
          - m.actualBoundingBoxAscent) / 100;
}

// Urbane Rounded 600 → .1811
// Proxima Nova   700 → .1164
// Avenir Next World  → .0740

      
    

    
Two things not to reach for.
      align-items: baseline looks like the right answer and is not — these parts do
      not share a baseline. Measured at xxxl it puts the currency and decimals
      11.8px below the numeral’s cap, which is most of the numeral’s height.
      text-box: trim-both cap alphabetic is the modern primitive for exactly this
      and would make the whole card unnecessary, but it trusts the font’s declared cap
      height: our Urbane Rounded reports 0.354em, roughly half its true cap, so the trim lands in
      the wrong place. It is worth retrying whenever the Urbane files are regenerated — and worth
      knowing that the browser will not tell you it went wrong.

  


  

    
The rule through the old price

    
The strike travels with the was-price slot, so its rules live here. Both of

Two things that break a strike

      

        
Fixed geometry drifts

          
A rule positioned at a fixed offset and width
            stops covering the number the moment the number changes — and the price changes on
            every coupon. Checkout’s was cutting through the KD instead.
            

The rule must live inside the struck price and span it:
            position:absolute with left/right insets, rotated about its own centre,
            so it tracks whatever width the price happens to be.

        
Figma’s angle is a half-turn out

          
Figma exports these rules at
            169.61deg and 170.13deg. Applied literally about a left
            edge, the rule swings almost a half-turn away from the text.
            

A line is symmetric under a half-turn, so the value you want is
            the Figma angle minus 180 — 170.13 → −9.87deg. Checkout’s
            shipping CSS reads rotate(-9.87deg), which is exactly that.

      

    

    
Prefer the real rule to text-decoration: line-through only where
      the design calls for the tilted stroke — the plain strike-through is correct for the
      was slot at small sizes and is what this page’s own specimens use.

The component owns metrics. Paint is yours.

    
Raised by the Checkout lane, who tried to adopt
      .dsp and found three places where its paint fought the frame. The division is
      now explicit: .dsp owns the row, the sizes and the alignment. Colour and
      weight are configuration, not something to fight.

    

      
--dsp-satwt

      
Satellite weight, default 700. Checkout’s plan-card
        /mo is Proxima Medium 500 per the frame — now a token, not an
        override.

      
--dsp-was-ink

      
The struck price, default #999999. The payment dock’s
        “before” price is #ED1C24 in the frame — grey is the common
        case, not the only one.

      
--dsp-ink

      
The live price. Set it per instance wherever the type’s default is
        wrong.

      
--dsp-curwt
--dsp-decwt
--dsp-perwt

      
Per-slot weight, each falling back to --dsp-satwt. A muted
        suffix beside a bold currency — checkout’s /mo — is the normal shape
        for a per-period price, and one token for all satellites couldn’t express it.

      
--dsp-cur-ink
--dsp-dec-ink
--dsp-per-ink

      
Per-slot ink, each falling back to --dsp-ink. Set only the
        slot that differs; the rest follow the type.

      
color

      
The sanctioned override surface. Gradient prices — checkout’s
        per-plan fills — set color: transparent with
        background-clip: text on .num and .cur. That is
        expected use, not a workaround: the component never positions by colour, so painting
        over it cannot break the alignment.

    

    
The rule behind all of them: a component that dictates paint gets
      overridden per instance, and then it is not a component any more — it is arithmetic
      wearing a class name. If adopting .dsp would mean overriding colour in three
      places, that is the system’s bug, not the lane’s.

      Verified in one instance with no local rules: a Bold red currency, a Medium
      #999 /mo, a red struck price and a gradient numeral all
      expressing together, margins unchanged, and an ordinary caller’s defaults
      untouched.

    
Worth knowing, since it’s a design
      question and not a code one: the Figma Price set does not mute its
      suffix — Tertiary md renders /day in the same Bold and the same ink as the
      rest of the row. The muted /mo is a decision in the checkout frame. The tokens
      let a flow express it either way; which one is right sits on Rashid’s sheet beside
      the 20-vs-15 currency question, since the two are the same kind of disagreement between a
      drawn screen and the component set.

// price(139.000) → the markup below. Slots are options, never string concatenation.
function dsPrice(v, o = {}) {
  const n = Math.abs(v), whole = Math.floor(n);
  const dec = o.decimals === false ? '' : '.' + String(Math.round((n - whole) * 1000)).padStart(3, '0');
  const cur = o.currency === false ? '' : `<span class="cur">${o.cur || 'KD'}</span>`;
  const was = o.was ? `<span class="was"><span class="cur">${o.cur || 'KD'}</span>` +
      `<span class="num">${Math.floor(o.was)}</span></span>` : '';
  const per = o.per ? `<span class="per">${o.per}</span>` : '';
  const minus = o.minus ? '<span class="minus">−</span>' : '';
  return `<span class="dsp ${o.type || 'secondary'} ${o.size || 'md'}">` +
    `${minus}${was}${cur}<span class="num">${whole}</span>` +
    `<span class="dec">${dec}</span>${per}</span>`;
}

// the six checkout call sites become six option objects:
dsPrice(q.total, { type:'primary', size:'xxxl', was:q.list })   // payment dock
dsPrice(d.perMo, { type:'tertiary', size:'md', per:'/Month' })  // duration row
dsPrice(m.price, { size:'md' })                                 // payment method

// Same trap as the web: .top aligns FRAMES and .firstTextBaseline aligns BASELINES.
// Neither is the law. Align cap tops with an explicit guide.
extension VerticalAlignment {
    private enum CapTop: AlignmentID {
        static func defaultValue(in d: ViewDimensions) -> CGFloat { d[.top] }
    }
    static let capTop = VerticalAlignment(CapTop.self)
}

// capOffset(for:) = (ascender − capHeight) × pointSize, from the UIFont metrics —
// the native twin of the --k constants. Read it from the font, never hardcode it.
func capOffset(_ font: UIFont) -> CGFloat {
    (font.ascender - font.capHeight)
}

HStack(alignment: .capTop, spacing: 0) {
    if let was { StrikePrice(was).padding(.trailing, 6) }
    Text(verbatim: currency).font(.dsCurrency(size))
        .alignmentGuide(.capTop) { _ in capOffset(.dsCurrency(size)) }
    Text(verbatim: whole).font(.dsNumeral(size, type))
        .alignmentGuide(.capTop) { _ in capOffset(.dsNumeral(size, type)) }
    Text(verbatim: decimals).font(.dsDecimal(size))
        .alignmentGuide(.capTop) { _ in capOffset(.dsDecimal(size)) }
}
.monospacedDigit()                       // see system/motion.html — counting numbers
.foregroundStyle(type == .primary ? Color.dsRed : Color.dsInk)

// Primary numeral = Urbane Rounded Demi Bold; Secondary/Tertiary = Proxima Nova Bold.
// Arabic: one family for every part (Avenir Next World) — the layout direction
// flips with the environment, the structure does not change.

On Rashid’s sheet

    
Three things the Figma set says that look like drift rather than intent. Left
      as-is and documented rather than “fixed” — they are his calls:

    

      
Two questions, and they pull opposite ways

      
Answer them separately and you can agree to both
        and get neither.

      
The checkout frame and the Price set disagree twice, and the disagreements
        point in opposite directions — the Checkout lane’s observation, and the
        reason these two belong on one page rather than two.


        The currency — frame 20px, set 15px. Taking 15 makes
        checkout more like the set.

        The suffix — frame mutes /mo to Medium
        #999, the set renders /day in the row’s own Bold ink.
        Keeping the muting makes checkout less like the set.


        So: one rule means the set gains a muted-suffix variant;
        the frame wins means the set takes the smaller currency.
        Either is a single change. Ruling on them one at a time is what produces two
        half-answers and a set that still disagrees with the screens.


        Both readings are verified at source, in different files — the set in Design System 1.0
        by this lane, the frame in Diet Station 4.0 by Checkout, who re-read the Decimal
        group and confirmed Proxima_Nova:Medium bound to
        text/disabled/default. Neither is a misreading; they genuinely differ.

    

    

      
Not blocking anything — the component ships either way

      
    
        
  1. xs and xxs lose the size contrast. At every step from xxxl down to sm the
          numeral is larger than its currency. At xs both are 12px and at
          xxs both are 10px, so the numeral stops leading and the row reads as flat
          text. Either that is deliberate for the smallest labels, or the currency should drop a
          step to 10 and 8.
    2. 
        
  2. The Decimal sub-component’s own size is overridden everywhere. Its
          Size property is set to lg on xs and xxs but md
          on lg/md/sm, and in every case the font size is overridden on the instance anyway. The
          property currently carries no meaning — worth either wiring it to the ramp or removing
          it, so the next person doesn’t trust it.
    3. 
        
  3. Two Figma sets disagree, and only one is canon. The Checkout lane reported
          that Figma’s own components contradict the rule; they are right, and the cause is
          worth knowing. The authored Price set (3551:1926) is unanimous —
          14 of 14 variants top-aligned. But the Pricing set on the
          “Pricing Modules” page has its Plan Price Details rows
          bottom-aligned, putting /month on the big figure’s baseline.
          Those rows have been restyled into Urbane Rounded and Proxima Nova but never converted
          — they still price in $19. They read as kit residue rather than
          intent, which would make Price canon and those stale; confirming that, or
          deleting them, stops the next lane rebuilding the old treatment faithfully from the
          file.
    4. 
        
  4. Three type names describe positions, not roles. Secondary sm,
          Secondary sm 2 and Secondary L sit beside a
          Size property that already says sm and lg, and two of the three appear
          only in the Arabic variants. This page documents them by what they do — struck
          was-price, and the Arabic secondary pair — but the names will mislead a developer
          reading the set cold.
    5.
